# 7774 - worker-prompt eval set
20 past issues (tools/evals/worker-cases.json: pre = master before the good PR, good = its land commit; 7 kinds). `tools/evals/run.mjs` replays a case in a throwaway worktree on the lowest worker model and scores by the end state: the stage checks the good PR added or changed must pass, required items done, tokens and minutes. The pure rules are in `tools/evals/lib.mjs`, proven by `evalharnesscheck`. The budget is the `evals` block of roles.json (20 cases, token caps, usage cap, model); run.mjs refuses beyond it. Cases whose result flips across `--repeat 3` are flaky and left out of the pass rate. Reports are `tools/evals/reports/<hash>.json`; the commander prompt requires one before a worker/enlarger prompt or tools.json change.
Not done here: the live 3x calibration run and the optional judge call (both cost real tokens). The first commander run of `--all --repeat 3` is the calibration and must be posted. The judge is unused until a case lists "required" items.
