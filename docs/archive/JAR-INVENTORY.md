## What the blockstate and model JSON look like

Two shapes, and the model system has to handle both (`docs/ARCH.md`):

- **`variants`** — `oak_stairs.json`: one entry per state string
  (`facing=east,half=bottom,shape=inner_left`), each naming a model plus `x`/`y` rotation and
  `uvlock`. ⚠ The rotation lives in the BLOCKSTATE, not in the model.
- **`multipart`** — `oak_fence.json`: a list of `{when, apply}` clauses; EVERY matching clause
  contributes geometry, and the post clause has no `when` at all.

⚠ Session 1 pasted both files in full here and one of them was truncated mid-JSON, which is
worse than not pasting it. `unzip -p <jar> assets/minecraft/blockstates/oak_stairs.json`
reproduces either one in a second.

## ⚠⚠ WHAT IS **NOT** IN THE 1.18.2 CLIENT JAR — read this before planning Track W

The tables above are complete. Note what is **absent**: there are **zero**
`data/minecraft/worldgen/**` entries. No biome JSON, no configured/placed features, no
carvers, no noise settings, no density functions, no structure sets, no template pools,
no processor lists.

**This is a fact, measured, and it changes the W track.** The plan cannot say "port the
worldgen JSON out of the jar", because it is not there. In 1.18.2 the vanilla worldgen
definitions live in code, not in the client jar's data directory.

**What IS there, and it is a great deal:**
- **866 structure NBT pieces** (`data/minecraft/structures/`) — the actual building blocks
  of villages, mineshafts, strongholds, outposts, ruins. **Structures really can be ported
  as data.** Only the *placement and assembly rules* need sourcing elsewhere.
- **900 blockstates + 1725 block models + 1235 item models** — the entire roster, its
  geometry and its rotations. The Foundation track is fully unblocked.
- **861 block textures**, of which **the old set covers most** (see the gap table above).
- **986 loot tables, 1058 recipes, 270 tags, 1141 advancements** — Track G's data spine,
  all present.

**How the worldgen definitions were obtained — CLOSED, session 2 (F6/W1).** Not from the jar
and not from Mojang's data generator: `tools/fetch-vanilla-data.mjs` mirrors 766 worldgen
JSONs from `misode/mcmeta` (branch `1.18.2-data`) plus the PrismarineJS `pc/` dataset into the
gitignored `.mcdata/` cache in about ten seconds (D-6). `docs/PLAN.md` §11 is the substrate
table. Three findings from the attempt are kept because they will come back:

- The 1.18.2 **client** jar does contain `net/minecraft/data/Main.class`, Mojang's data
  generator entry point — but running it needs the launcher's `libraries/` on the classpath,
  and those are not in the jar.
- ⚠ **`piston-data.mojang.com` is not reachable** from the cloud container or from Dan's
  device shell — the egress policy refuses it, measured both ways. The server jar cannot be
  downloaded; anything that needs it must run against the client jar plus local libraries.
- The 1.18.2 manifest asks for Java 17. A newer JRE generally works, but that is worth
  verifying rather than assuming.

**Scheduling consequence, and it held:** Foundation needed only blockstates, models, textures
and items, all of which are in the jar, so F was never blocked on any of the above.
